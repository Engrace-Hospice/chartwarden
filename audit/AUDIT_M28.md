## GRADE: PASS WITH MAJOR GAPS

**Counts: 0 BLOCKER / 4 MAJOR / 7 MINOR**

Module 28 is an unusually disciplined interop spec. Its central architectural decision — **the reader-seam-only data path** (M28 cannot read any PHI table except through a published owner reader seam, enforced by the dependency-cruiser boundary check) — is exactly the right inversion of the "interop layer touches all PHI" anti-pattern, and it satisfies ARCH-282/ARCH-281#6 and the spec's claim to *not* write or own any other module's clinical tables. The 42 CFR Part 2 default-on egress redaction (D3/D20), the propose-then-review inbound pipeline that never blind-writes M5/M12 tables (D8), the per-read `auditRead()` §164.528 disclosure trail (D15), the AI-prohibited-zone boot validator (D14), and the dual-approval per-recipient client registry (D12) are all correct and well-evidenced.

It does **not** earn a clean PASS for four reasons: (1) it pulls **Phase-3 R4 *write* (inbound import)** into Phase 1 without an ADR, contradicting the architecture phase cut; (2) the FHIR `$export` — the single largest PHI-egress surface in the platform — does **not** map onto the SEC §8.5.2 bulk-export control set (justification, approver, 10,000-record cap + elevated approval, severity≥critical for >1,000 records); (3) the spec depends on a **major dependency-graph expansion** that, while procedurally correct (explicit manifest patch per ARCH-235), silently surfaces an architecture §11-vs-§20 internal conflict it should flag rather than resolve unilaterally; and (4) it asserts an undefined `compliance_42cfr_part2` retention class and three foundation package names (`packages/storage|cache|queue`) that do not exist in the authoritative architecture.

No BLOCKER: the module respects every architecture *invariant* (RLS on every owned table, no helper-table direct access, no roll-your-own auth/crypto, no cross-tenant query shapes, SUD segregation present, no clinical-table writes), so it neither fails a CI fitness check by design nor creates direct HIPAA/Part 2 legal exposure nor makes another module unbuildable.
