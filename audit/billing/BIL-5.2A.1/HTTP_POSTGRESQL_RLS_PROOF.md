# HTTP/PostgreSQL proof

The existing M41 live route suite includes a submission-first feed case using the private live harness, actual Fastify route registration/auth guards and the `chartwarden_app` connection. The fixture puts an uncertain submission behind 60 newer claims; the ordinary page omits it while the in-doubt endpoint returns it. A second test creates another tenant/provider claim and an out-of-caseload claim under the same tenant/provider. The authorized feed excludes both, returns only a lower-bound loaded count, rejects a provider-B query, and returns 404 for a guessed tenant-B detail.

The same M41 Fastify test application also registers the real M23 claim routes and Drizzle read service. It creates M23 in-doubt attempts in two organizations and calls the M23 feed as tenant A; only A's submission is returned, provider-B and guessed tenant-B detail reads return 404. The separate M23 validation-overview live suite additionally tests the source reader under the restricted role with 60 later ordinary claims, provider narrowing, tied attempt timestamps and cursor continuity.

Both suites run through `scripts/test-m25-835-ingestion-private.sh`, which provisions a fresh private `chartwarden-postgres:dev` container and uses the restricted `chartwarden_app` role for application reads. The Fastify tests use the repository's synthetic `x-test-user` authentication adapter. The M41 caseload port is exercised with an allowlist fixture (authorized patient vs. same-provider out-of-caseload patient); the test does not certify the M5 caseload storage adapter or deployment IdP. It proves application authorization and M23/M41 RLS query isolation. Exact execution outcomes are in `TEST_RESULTS.md`. No shared or production database is used.
