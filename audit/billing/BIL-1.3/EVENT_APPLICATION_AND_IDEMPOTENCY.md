# Delivery, ledger and atomicity

Migration 1354 creates `claimmd_ack_delivery` (one row per captured event and mode) and append-only `claimmd_ack_application` (one row per processing attempt). The delivery trigger seeds both `shadow` and `apply` rows when a BIL-1.2 resolution becomes `resolved`; existing resolved records are backfilled. Account reference, usage and mode partition the durable work. A platform worker claims at most 25 due rows with `FOR UPDATE SKIP LOCKED`, leases for 90 seconds, and applies bounded exponential retries. After repeated failures, work enters `needs_review`; safe error codes are stored, never exception text.

`claimmd-ack/store.ts` decrypts the original BIL-1.1 page under audited platform context and checks the event digest. It never calls Claim.MD or touches the response cursor. `claimmd-ack/service.ts` acquires a transaction advisory lock by event UUID, checks for an already applied event, re-reads the current resolution with a shared row lock, revalidates immutable submission evidence and historical encrypted TIN, and calls the owner adapter. The claim change, M41 outbox, and final application row commit in one `withOrgContext` transaction. The ledger's unique applied-event index and per-attempt unique key cover concurrency and crash replay.

If tenant commit succeeds but the platform completion mark crashes, the lease expires. The next worker observes the application ledger and only marks delivery complete. If tenant commit fails, no ledger or claim mutation is committed and the delivery retries. A held identity/state decision is retained as an immutable ledger attempt and retried with backoff; after the cap it requires operator review. A shadow decision is separate from apply delivery and never mutates claims.

The ledger contains account, usage, tenant, provider, location, claim, submission, evidence UUID, resolution ID/version, message response ID, interpreter version, proposed action, outcome, previous/new state and safe reason code. Original text, NPI, TIN and vendor IDs remain in the protected encrypted source/evidence stores. `claimmd_ack_application` is tenant RLS protected, FORCEd and append-only; the queue is platform-only. No financial entry is produced.

**Runtime certification still required:** demonstrate advisory lock, share lock privilege, RLS, triggers, grants, crash recovery, concurrent workers and transactional outbox under the real non-bypass app/platform roles in a private PostgreSQL cluster. Static DDL checks cannot prove those behaviors.
