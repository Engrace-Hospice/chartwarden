# M25 staging integration

The current M25 pull path is not safe for a no-posting Claim.MD handoff: `ingest/clearinghouse-pull.ts` calls `receiveAdvice`; the Drizzle service inserts remittance advice and emits `m25.edi.835_received`; the live binding calls `postAdvice`, which inserts lines/adjustments and publishes financial effects. See `apps/backend/src/modules/25-remittance/ingest/clearinghouse-pull.ts`, `ingest/service-drizzle.ts`, and `outbox-consumers/live-binding.ts`.

This branch does not call that path. Migration 1356 adds `claimmd_era_m25_stage`, with tenant RLS and source pointer, account/environment, provider/location, interchange and transaction control identities, digest, safe evidence, state, and reason. `claimmd-era-stage.ts` adds a M25-owned `stageVerifiedClaimMdEra` operation: it requires injected captured-source and M1 provider/location proof, enters `withOrgContext`, checks M25 existing advice for exact digest/control duplicates, holds matching check trace + exact decimal amount as possible duplicate, and writes only the stage row. It does not call `receiveAdvice`, `postAdvice`, or an outbox. The operation is not yet wired to parsed X12 or to capture delivery; the feature flag therefore fails startup.

Required service: accept only a captured inbox UUID after validating account/environment, exact provider owner under M1 reader, parsed X12 identity, conflict/duplicate decision, and current tenant context. It must persist only staging evidence, must not emit `m25.edi.835_received`, and must be idempotent on source inbox/file/ST. Delivery retry must not be coupled to posting. Existing manual/SFTP workflows remain untouched by this change.
