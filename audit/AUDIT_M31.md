## GRADE: **FAIL** (≥1 BLOCKER)

**Counts: 3 BLOCKER / 9 MAJOR / 8 MINOR**

The spec is unusually thorough and well-written, but lock-grade is graded on conformance and compliance, not prose. It commits two structural architecture violations (an out-of-bounds dependency expansion and new client apps/packages it tries to legislate into the manifest) and one HIPAA/architecture retention inversion (telehealth recording retention). A beautifully written spec that rewrites the manifest dependency graph and inverts a retention default FAILS.

## Dimension Coverage Notes (A–J)

### A. Architecture conformance — **FAIL**
- **dependsOn:** Manifest fixes `[5,7,8,22,36,39]`; spec expands to 24 (M31-F01, BLOCKER). The spec is candid that the original was "a placeholder" (D19) — but the architecture's §20 table is authoritative, not a placeholder, and the only sanctioned manifest changes when speccing a module are: fill ownedTables, confirm codePaths, update dependsOn *if it consumes a new module via a reviewed architecture decision* (ARCH-146/ARCH-235). An 18-module expansion is not a within-spec edit.
- **ownedTables:** 15 tables declared (§13), none colliding with Modules 1–4's pre-claimed tables (ARCH-143) — **conforms**. Helper-only tables (`audit_event`, `outbox_event`, `idempotency_key`) are not claimed — good; but the spec mis-attributes the outbox helper to M38 (M31-F04).
- **codePaths:** Spec adds `apps/staff/portal-admin`, `packages/portal-api-contracts`, `packages/telehealth-client/vendor-adapter` — out-of-bounds new client app/packages (M31-F03, BLOCKER; SD-001).
- **Cross-module reads via owner repos, not schemas:** The spec's outbox-only + reader-seam discipline is correct in intent (§8.8 dependency-cruiser rule), and it explicitly forbids cross-schema imports — **good**. The problem is the *number* of owners it reads from (F01), not the mechanism.
- **Vendor adapter confinement:** Daily.co SDK confined to `packages/telehealth-client` with a depcruise rule (§8.5) — **conforms** to the adapter mandate (ARCH-145; Daily.co is hand-rolled, not in VENDOR_ADAPTERS, which is acceptable — but if `@daily-co/daily-js` is an SDK it should be registered in VENDOR_ADAPTERS so it can't leak; minor).
- **Outbox/idempotency/seams:** Outbox-in-same-transaction (§2.4) — good; consumer idempotency on `(eventId, consumerName)` — good; `validateSeams()` boot refusal — good; eraser seam present but registrar mis-named (M31-F15).

### B. System design conformance — **partial**
- Stateless app tier, BullMQ queues with concurrency declared (§4.8) — **conforms** (SD-005/SD-062/SD-064), though queues do not declare retry/backoff/DLQ explicitly (SD-059) — gap folded into ops notes.
- RLS session-var naming wrong in prose (M31-F09). Cursor pagination absent (M31-F06). Idempotency-Key per-route absent (M31-F10).
- MinIO recording path `tenant_{org}/telehealth_recording/{visitId}/` — note SD-033/SD-034 canonical prefix is `tenants/<org_id>/recordings/`; the spec uses `tenant_{org}/telehealth_recording/` (singular `tenant`, different sub-bucket). Minor drift (folded into F12 family / not separately scored).

### C. Security hardening — **partial / strong intent**
- requirePermission + ABAC on every PHI route (§4.1 "every PHI route declares `requireReadAudit`", §8.2 boot-fails on missing ABAC) — **conforms** to ARCH-281#8.
- Read-audit on every portal page-load (`portal_audit_view` + `auditRead()`) — **conforms** (ARCH-041/ARCH-281#9), and is well-designed for §164.528.
- Does NOT roll its own auth/crypto (delegates to M2/M1 DEK) — **good**. But it *does* roll its own rate limiting and never cites SD-055 (M31-F07, MAJOR).
- DTO discriminated-union leak guard (D17/§8.4) — excellent minimum-necessary control.
- STRIDE table present (§8.3) — **conforms** (SEC-007).
- Wrong RLS session var (M31-F09).

### D. HIPAA — **mostly strong, one inversion**
- §164.528 disclosure accounting, §164.526 amendment, §164.524 access, 42 CFR Part 2 SUD redaction-by-default (SQL-filtered upstream behind consent), minimum-necessary DTO discipline — all **well-covered** (§1.3 table).
- **Recording retention inversion (M31-F02, BLOCKER)** — 10-year floor vs 90-day default is a data-minimization liability.
- **Invented M39 consent types (M31-F05, MAJOR)** — post-death/bereavement access rests on consent types M39 doesn't define.
- No-PHI-to-vendor: adapter sends opaque room IDs + short-TTL tokens, with CI grep guards (§8.5) — **conforms** (SEC-015/SEC-048; INT-039 "video is PHI" handled by keeping identity opaque). No PHI in push (M36-mediated, generic) — **conforms** (SEC-048).

### E. AI governance — **conforms**
- D12 hard-block: M32 may not register any prompt mutating a portal write path; `validatePortalAIBlock()` boot validator walks M32's registry (§8.7). Read-only summarization (lay-language polish) is HOTL display-only and gated behind a deny-stub until M32 ships `NarrativeEnhancementProvider` (§1.1, §8.7). This is consistent with AI-001/AI-002/AI-008/AI-031/AI-062. **No AI write path; portal-AI patient consent deferred correctly.** Conforms.

### F. DR/BCP — **gaps**
- No DR tier declared; D-4 (Tier 3 vs 4) unaddressed (M31-F11, MAJOR).
- Telehealth degraded-mode (audio-only fallback, reschedule, "never blocks chart writes") — **conforms** to DR-060/INT-045 governing invariant (patient care never blocks on a Tier-3/4 external dependency). §7.10 vendor-outage flow is correct (fail-fast, banner, clinician decides, circuit breaker).
- BullMQ consumer idempotency asserted (§2.6, §4.10) — satisfies DR-022.
- Portal is not a safety-critical (DR-070) data owner — it reads; correct.

### G. Operations — **partial**
- Partitioning declared for `portal_audit_view` and `telehealth_webhook_event` (monthly RANGE by created_at) — **conforms** to OPS-020 pattern; must be added to `partition.rotate` (OPS-021) — spec mentions a `m31.disclosure-accounting-rotate` cron (§4.8) but should defer to the platform `partition.rotate` job, not a module-local rotator (minor).
- Queues lack explicit retry/backoff/DLQ params (SD-059/OPS-035) — should be declared.
- Secrets: Daily.co webhook HMAC secret + VAPID keys rotation referenced (§12.4) but not entered into the secret inventory with a cadence (OPS-036) — minor.

### H. Integrations — **mostly conforms**
- Telehealth (Daily.co) matches INT-005 row 21 / INT-039: bidirectional REST + WebRTC + webhooks, video=PHI, BAA required, platform-or-per-tenant cred (TBD ADR-003), room creation idempotent per `telehealth_visit_id`, webhook signature-verified + idempotent on `(vendor, vendor_event_id)`, audio-only fallback, no chart-write dependency — **conforms**. Daily.co is in the BAA register (arch line 2235) and the spec gates activation on BAA (`validateTelehealthAdapterBaa`, §4.4) — good (INT-014).
- Webhook security (HMAC + replay/idempotency + no clear-text PHI logging via `vendor_payload_minimal`) — **conforms** (INT-016/SD-056).
