# WardenX Module Audit — Module 29: External Interfaces (HL7v2 / ADT / Labs / NPPES / Outbound)

**Spec audited:** `WARDENX_MODULE_29_EXTERNAL_INTERFACES_SPEC_v0_4.md` (Locked v0.4 Consolidated)
**Auditor protocol:** `audit/_criteria/AUDITOR_INSTRUCTIONS.md` v1.0
**Authoritative sources verified by Grep:** ARCHITECTURE v0.11, SECURITY_HARDENING v0.2, INTEGRATIONS v0.1, SYSTEM_DESIGN v0.3 (criteria packs ARCH-/SD-/SEC-/AI-/DR-/OPS-/INT-).
**Manifest (authoritative):** M29 `dependsOn: [5, 11, 40]`, `codePaths: ["apps/backend/src/modules/29-external-interfaces"]`, `ownedTables: []` (to be filled by spec).

## Grade: **FAIL** — 4 BLOCKER / 7 MAJOR / 9 MINOR

ARCHITECTURE WINS. The spec is unusually thorough in prose and clearly understands the perimeter-ingress security model (propose-then-review for ADT, mTLS+allowlist, BAA gate, SUD ingress gate, audit denylist). It fails because it (a) introduces an unauthorized JVM/Java worker tier, (b) claims NPPES sync + canonical-cache ownership the architecture assigns to Module 40, (c) ships a wire-persist-before-redact design that directly contradicts its own SUD-strip-before-persist design with HIPAA/Part 2 exposure, and (d) carries pervasive schema-vs-implementation drift that would defeat its own audit denylist and break boot. The proposed manifest patch is itself self-inconsistent (omits consumed M6/M8/M19).

## Dimension Coverage Notes (A–J)

**A. Architecture conformance.** Two BLOCKER-level breaks: unauthorized JVM worker (F01) and NPPES ownership collision with M40 (F02). The proposed manifest patch (D24) is the right *mechanism* (ARCH-235 explicit edit) but is self-inconsistent — omits consumed M6/M8/M19 (F05). Owned-table list is otherwise well-formed and non-colliding for the eleven HL7/feed tables (no other specced module claims them); `nppes_provider`/`nppes_sync_run` are the disputed pair (F02). Helper-only tables (audit_event/outbox_event/idempotency_key) are correctly consumed via helpers, never owned. Adapter mandate handled correctly for Xero/Gusto (consumed from M27 — INT-005 confirms owner 27,29) and for the NPPES HTTP client (`packages/nppes-client`). The dependency-cruiser rule set (§13.2) is thoughtful. ABAC predicates executing raw queries on M29 schema from M3's package is a latent ownership concern (F08).

**B. System design conformance.** Listener supervisor as a sibling OS process (crash isolation) is reasonable and stateless-app-tier-compatible. SD-004 worker-tier violation is the headline (F01). gRPC-over-UDS is a non-standard internal transport vs SD-009/ARCH-195's "internal HTTP with TypeBox JSON + mTLS." Idempotency-Key 24h/409 semantics on admin routes asserted (D14) — consistent with SD-053. Cursor pagination not explicitly stated on the PHI lab/message lists (SD-052) — gap.

**C. Security hardening.** Strong: mTLS 1.3-only + per-feed pinned client-CA + sender IP allowlist + revocation list (D23, SEC-024); step-up on mutating/credential/disclosure routes (D18); STRIDE matrix present (SEC-007); RLS on all tenant tables + platform-scope policy on NPPES (SEC-008). Weak: F04 (denylist targets non-existent columns → PHI capture risk, SEC-048), F08 (authz wiring inconsistent), F16 (plaintext-view quota generous vs SEC-052). Fail-closed boot validator (W-XI-15) is a good SEC-001(4) pattern.

**D. HIPAA.** F03 (SUD/Part-2 persist-before-redact contradiction — direct Part-2 ingress exposure) is the gravest. F07 (§164.528 mis-citation + retention contradiction). Audit-denylist column-name mismatch (F04) risks PHI in audit bodies. `auditRead()` on every payload/lab/proposal route is correctly mandated. No-PHI-in-notification-payloads honored (deep-links via M36, §5.3). Minimum-necessary at the boundary (D19 segment denylist) is good in intent but undermined by F04.

**E. AI governance.** M29 invokes no AI (§8.6) and explicitly defers probabilistic matching to a Phase-2 M32 seam under HOTL governance. Conformant; nothing bypasses the AI lifecycle. The deterministic-cascade-only Phase 1 cut aligns with D6.

**F. DR/BCP.** F09 — no tier declaration, no degraded-mode (available/limited/unavailable) mapping, no sender-queue confirmation. BullMQ-idempotency invariant (DR-022) only partially satisfied (F10/F06).

**G. Operations.** Queue catalog with retry/backoff/DLQ present (§4.9, ARCH-262) — good. Partitioning by month on hl7_message_inbound/outbound declared (must be added to `partition.rotate`, OPS-021 — not stated). Secret inventory/rotation for per-feed certs not wired (F18, OPS-036). Migrations forward-only with phased plan (0029→0031) — acceptable.

**H. Integrations.** ADT (INT-036) and Lab (INT-037) contracts largely matched: MLLP, A01/A03/A04/A08/A11, per-tenant/per-feed, allowlist, BAA, propose-then-review for ADT, auto-attach for labs, idempotent on control ID. Deviations: lab dedup on wrong key (F06); NPPES ownership (F02). No inbound CMS webhook receivers invented (good, INT-044). No WardenX-held Surescripts/PECOS/EVV-aggregator inventions. Xero/Gusto correctly consumed from M27 (F17 is a modeling nit, not an invention).

**I. Medicare hospice regulatory correctness.** M29 encodes little hospice regulation directly; it cites CoP 418.104(a) (physician-order documentation via lab-to-order back-link) and HIPAA/Part-2. No election/cert/F2F/NOE/cap encodings to mis-state. The lab→order fulfillment link is plausible but depends on M11's order model (cross-module, forward-stub). No Medicare-correctness BLOCKER.

**J. Internal quality.** This is where the spec is weakest: F04 (three incompatible vocabularies), F12 (D6 four-vs-five), F13 (W-XI-01 residual auto-apply), F14 (outbox count 27/29/33), F15 (Drizzle import/type errors). The prose is excellent but the artifact has not been reconciled across its own sections post-consolidation.
