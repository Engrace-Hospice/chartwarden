## 1. Decide: one submission port for Medicare, Medicaid and commercial
**Labels:** `needs-decision`, `P1`, `area/integration`, `area/backend`
**Scope note.** The transport is the common port for all three lanes. Medicare moves first. Medicaid today does not use it:
M24 submits through per-provider-entity state credentials and the Oregon gateway in `packages/medicaid-adapters`. Decide
per state whether the state channel (a) is wrapped as a transport, or (b) stays a state-direct adapter behind the same
fail-closed capability gate. Oregon can stay direct; the decision must not force a Medicaid rewrite. Commercial uses the
transport from the start (issue 20).
**Problem.** Two submission paths exist. The M23 workers use the legacy launch gateway; the ADR-0053 transport is bound
at boot (`apps/backend/src/index.ts` ~3503) and only logged (~12426). ADR-0053 is still "Proposed".
**Decision needed.** (a) Transport becomes the only path and the gateway is retired after a pilot (recommended);
(b) both stay, chosen per provider entity; (c) skip a direct-MAC adapter and cut over to Stedi.
**Done when.** ADR-0053 is amended with the choice and the consequences, `arch:adr-docs` passes, and issues 2 and 3 are
re-labelled `ready-for-agent`.

## 2. Add a `direct_mac` transport that wraps the existing gateway
**Labels:** `enhancement`, `P1`, `area/integration`, `area/backend`, `ready-for-agent` (after #1) · **Depends on:** 1
**Problem.** `CLEARINGHOUSE_VENDOR=direct_mac` is accepted by the registry but has no factory, so the process refuses to boot.
Without a second implementation the port is proven against Stedi only (plan item B1).
**Scope.** Register a `direct_mac` factory in `buildClearinghouseFactories` that maps `submitClaim`/`submitNotice` to the
existing `X12ClientPort.generate*` plus `MacPortalPort.upload`, and `fetchAcknowledgments` to the 999/277CA pulls, with
stage tagging per ADR-0053 D2.
**Acceptance.** Passes every `CLEARINGHOUSE_CONFORMANCE_CASES` case (capability-tag and justify any it cannot meet);
fails closed with `CH_NOT_WIRED` when unconfigured; no new network access outside `*-client`.

## 3. Inject the clearinghouse binding into the M23 submit and acknowledgment workers
**Labels:** `bug`, `P1`, `area/backend`, `area/integration` · **Depends on:** 1, 2
**Problem.** `clearinghouse-binding.ts` states the binding is "NOT yet injected into any M23/M24/M25 caller". Setting
`CLEARINGHOUSE_VENDOR=stedi` therefore changes nothing about how claims are sent.
**Scope.** Add a `transport` dependency to `buildM23WorkerDeps`. When `binding.vendor` is set, the claim, NOE and NOTR
submit/retry workers and the ack pull use it; otherwise they use the legacy ports. One env switch; no silent fallback
between the two when a vendor is set.
**Acceptance.** A test fails if a worker is built without the binding while a vendor is configured; a live suite shows a
clean claim goes READY to SUBMITTED through the in-memory clearinghouse; grep of `index.ts` shows the factory consumed;
`check:boot:platform` still passes.

## 4. S01: one live suite for the whole Medicare claim cycle
**Labels:** `enhancement`, `P2`, `area/test`, `area/backend` · **Depends on:** 3
**Problem.** Submit, acknowledgment, 835 and posting are tested separately. Nothing proves they fit together.
**Acceptance.** A single live test: assembled valid claim, submit through the in-memory clearinghouse, clearinghouse-stage
then payer-stage ack, 835 matched by CLP01, posted exactly once, claim state and ledger agree.

## 5. S05: worker-level crash and UNKNOWN-outcome tests
**Labels:** `enhancement`, `P3`, `area/test`, `area/backend` · **Depends on:** 3
**Problem.** The Stedi adapter and attempt store handle ambiguous sends well, but no test kills a worker.
**Acceptance.** Cases: killed before send, after send before response, after response before commit. Each ends with a
single logical submission, an UNKNOWN attempt surfaced for reconciliation, and no blind resend; the operator resolve
route clears a stale attempt and writes the audit actor.

## 6. S12: commercial 835 with no candidate provider must go to manual review
**Labels:** `bug`, `P2`, `area/test`, `area/backend`
**Problem.** `ingest/service.ts` documents that commercial advices get zero automatic candidates, but every 835 live test
uses `payerKind: "medicare"`. The fail-closed behaviour is untested.
**Acceptance.** A live test ingests a commercial advice; nothing auto-posts; lines appear in the manual-match queue;
cross-tenant isolation holds. If the behaviour differs from the documentation, fix the code, not the test.

## 7. S11: refuse electronic submission for states without a Medicaid gateway
**Labels:** `bug`, `P2`, `area/backend`, `area/frontend`
**Problem.** Only Oregon has a live Medicaid gateway; WA, ID, CA and NV are deny-stubs. No test shows a submit attempt
for those states is refused with a message and an alternative workflow.
**Research.** `docs/audits/billing-e2e/MEDICAID_STATE_CHANNEL_RESEARCH_20261023.md` covers all 50 states and DC from public
pages: 40 explicitly allow clearinghouse submission (with trading-partner enrollment and usually testing), 5 are implied, 5
not found, TN has no fee-for-service channel. It is unverified; use it to prioritise outreach, not to enable a state.
**Before coding.** Check `packages/db/src/schema/medicaid-billing/trading-partner.ts` and the credential tables for what
already records per-state capability; do not add a new capability table if they suffice.
**Acceptance.** Runtime refusal with a stable code, an API/UI message naming the alternative (manual or paper), a test per
stub state, and no queue job enqueued.

## 9. S13: claim straddling 1 October and FY2027 rate reconciliation
**Labels:** `enhancement`, `P2`, `area/test`, `area/backend`
**Problem.** Rate versions are tested by service date, but not a claim whose billing period spans two fiscal years. FY2027
rates are not reconciled to a CMS source in any test.
**Acceptance.** A claim-level test splits days across the boundary and uses the right version for each; a source register
lists the CMS tables used for FY2027 with a golden fixture per rate component and wage index; any mismatch is a finding.
