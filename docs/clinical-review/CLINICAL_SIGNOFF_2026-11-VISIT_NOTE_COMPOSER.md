## How to use this sheet (about 30 minutes)

1. Read the **flagged rows first** (the "Reviewer must decide" cell starts with `FLAG.`; listed in the next section).
2. For each row mark one box in the last column: **A** approve as worded, **E** edit (write the replacement in the row or in the margin),
   **R** reject (remove the item). A blank box means not reviewed.
3. Wording is copied verbatim from the code. `${name}` is a value the clinician or the system fills in. The code is the source of truth:
   if a row and the code differ, the code is what clinicians see. Where the code builds a sentence from a constant (for example 7, 15 or
   the 2 to 3 range) the row shows it as rendered. Cite a row by its id, for example `2.13`.
4. "Source type" uses: regulation (42 CFR text), CMS guidance (interpretive guidance, HOPE manual), quality measure (HQRP reporting),
   guideline (published clinical guideline), common practice (industry resource), research benchmark, or **agent judgement** (no cited source).

**What an approval changes.** Nothing in code reads this sheet. The corpus review constant `CORPUS_CLINICAL_REVIEW`
(`packages/narrative-vocab/src/vocabulary.ts`, reviewer ADA, status `pending`, `reviewedVersion` null) covers the narrative corpus
only (here: the sixteen pain statements, 2c); it is approved by a deliberate edit in its own commit that names the release (VN-D34). It gates
only the per-tenant draft switch. The pain helper, the plan-of-care prompt, the late-entry card, the next-visit panel and the section chips
read no tenant switch, so they reach clinicians on deploy whether or not this sheet is signed. The ESAS-r prompt (section 8) differs: it sits in
the composer's draft rail, so it appears only where the tenant draft switch is on (row 8.9). No code constant records review of items
outside the corpus.

### 3d. Source disagreements and unsourced items recorded by the research

Disagreements (visit-plan research B9 and C7): the 15-day clocks are rolling while HOPE windows are fixed, and no source says a HOPE update visit can
double as the 15-day update; the 15-day review and 14-day aide visit are conditions of participation, the HOPE visits are quality-reporting
only; who may do which visit differs by rule (initial assessment by an RN; follow-up by RN or LPN); RN visit cadence has four different
instruments (no rule, NHPCO scrutiny at 14 or more days, CMS HCI gaps over 7 days, one agency's weekly policy); NCCN 2019 gave 60 and
15 minute reassessments, NCCN 2025 says "regularly"; SOM revision dates are mixed (Rev. 222 versus tag text from Rev. 210).

Not sourced: any federal minimum visit frequency for routine home care; a federal visit-note template; a requirement that each note carry the next
visit date; a rule for a call within 24 hours of a medication change; a CFR requirement for a missed-visit reason or for notice of a
changed schedule; teach-back as a hospice requirement; the aide 14-day visit when no aide is assigned; telehealth for routine visits; state law.

## 8. ESAS-r item prompt (added after the sections 1-6 sign-off; signed off separately by Lora, RN on 2026-11-25)

`apps/web/src/modules/08-encounters/esas-symptom-prompt.tsx`; rule in `packages/types/src/esas-symptom-prompt.ts`. Shown under the ESAS-r total in the composer's
score-trend panel (Right Panel). It reads the nine item scores of the latest scored ESAS-r reading up to the visit, the same reading as the total above it. It shows
nothing when the reading carries no item scores or no item reaches the cut-off. Advisory: no button, link, tier or band, and nothing blocks save, finalize or sign.
Built after the signature of sections 1-6, so that signature does not cover it; this section has its own sign-off record (Lora, RN, 2026-11-25). The code header records this sign-off;
the research doc is "research input, not clinical sign-off" and marks what a source did not confirm.
**It sits behind the tenant visit-note draft switch** (row 8.9, Release impact).
Research: [`ESAS_R_CUTOFFS_RESEARCH.md`](../research/ESAS_R_CUTOFFS_RESEARCH.md).

## Release impact

> - `VOCAB_VERSION` moves from `narrative-vocab@2026.12.5` to `narrative-vocab@2026.12.6` (sixteen pain statements added; no earlier phrase changed). A visit-note
>   selection saved under the old version and not yet finalized gets `409 VOCAB_VERSION_MISMATCH` until the clinician saves it again.
> - The corpus review state stays `pending`; it gates only the per-tenant draft switch, not the helper, the prompts, the late-entry card, the next-visit panel or the chips (see "What an approval changes").
> - Notes more than 3 days late cannot be signed from the web (row 4.5).
> - Section 6 (no skin or wound concerns) was still being wired by another agent when this sheet was written.
> - Section 8 (ESAS-r symptom prompt) was built after the 2026-11-25 signature of sections 1-6 and was signed off separately (section 8 record). Unlike the pain helper, the prompts, the late-entry card,
>   the next-visit panel and the chips, it is behind the tenant visit-note draft switch: it renders inside the composer's draft rail, so it appears only where the draft is
>   switched on and a section is drafted (row 8.9). The switch is off by default and the server refuses to enable it while the corpus review is `pending`, so as the code stands
>   the prompt does not reach clinicians on deploy by itself unless a tenant already has the switch on. Its data path has no switch: the M9 scale-series route returns the nine
>   ESAS-r item scores (`itemScores`) to a holder of `assessment.read_trend` as soon as it is deployed.
