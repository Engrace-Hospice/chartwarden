# WardenX Module Specifications — Index

> **Canonical location for all module specs.** LLMs and contributors: every WardenX
> module specification lives in this directory (`docs/modules/`). The Module 29
> forward-engineering sub-tasks live in [`module-29-tasks/`](./module-29-tasks/).
>
> **Authority:** Per the audit charter, the architecture documents in
> [`docs/architecture/`](../architecture/) (`WARDENX_ARCHITECTURE_v0_11.md`,
> `WARDENX_SYSTEM_DESIGN_v0.3.md`, and the security / AI-governance / DR-BCP / ops /
> integrations docs) are **authoritative**; these module specs are **implementation
> proposals**. If a module conflicts with architecture, **architecture wins**.
>
> Module ownership (codePaths, ownedTables, dependsOn) is enforced by
> `architecture/module-manifest.ts` and `scripts/check-table-ownership.ts`.
>
> **Versioning convention (gate-checked):** specs are **re-locked in place** — the filename's
> version is pinned at first lock and never renamed; the spec's *header* (its `**Spec status:**` /
> `**Spec version:**` / `**Version:**` field) is authoritative for the current version, and the
> "Spec ver" column below tracks the **header**, not the filename. `bun run arch:module-docs`
> (`scripts/check-module-docs.ts`) enforces this index's parity, header-version agreement,
> ADR-citation resolution, and relative-link integrity. Four-digit `ADR-NNNN` cites must resolve
> to [`docs/adr/`](../adr/); citations paired with an `ARCH-nnn` audit-finding id are the 2026-06
> audit era's own ADR numbering (a historical namespace, exempt), and bare short `ADR-00N` refs
> are the architecture §21 open-decision register (see its numbering note).
