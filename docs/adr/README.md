# WardenX Architecture Decision Records (ADRs)

These ADRs are the repository's authoritative decision records. The corpus began with the
**Phase 0 remediation** of the architecture corpus (ADR-0001…0029, in response to the consolidated
compliance audit `audit/AUDIT_CONSOLIDATED_FINAL.md`, 2026-06-11, and the per-module
`audit/AUDIT_M*.md`), then grew: ADR-0030…0035 are frontend/build governance decisions, and
ADR-0036…0045 are post-build records ratifying deliberate as-built divergences and closing
register items (`audit/ARCHITECTURE_DOC_REMEDIATION_PLAN.md` + the 2026-08-14 ADR-compliance
audit). Code-vs-decision compliance is audited in `audit/ADR_COMPLIANCE_AUDIT_2026-08-14.md`;
corpus integrity is gated by `bun run arch:adr-docs`.

**Authority.** Per the auditor protocol, *architecture documents are authoritative and module
specs are proposals.* Several BLOCKER findings originate in the architecture documents
themselves; those documents have been corrected in place, and each correction is recorded
here as an ADR. Where an ADR and an older sentence in a spec disagree, **the ADR wins** until
the spec is re-locked against it.

**How corrections are recorded.** Each touched document carries an in-place edit plus a dated
*Remediation Changelog* section that cites the relevant ADR(s) and audit finding ID(s). The
ADRs below are the normative rationale those changelogs point to.

## Conventions

- ADRs are immutable once Accepted. A later decision **supersedes** rather than edits a prior one.
- Each ADR lists the documents it changes; those documents cite the ADR back — Phase-0-era via a *Remediation Changelog* section, the post-build corpus via the divergence banners / inline citations (e.g. `WARDENX_ARCHITECTURE_v0_11.md`'s §4 banner).
- Phase 1+ module re-locks must conform to these ADRs and cite them in their own changelogs.
